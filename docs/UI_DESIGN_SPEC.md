## 1. 品牌基础

### 1.1 产品定位

零一智鉴是面向 AI API 使用者、中转站评估者和自托管团队的 API 真测平台。它以真实探针、官方基线、协议字段、评分与可追溯报告回答三个问题：

1. 接口提供的模型是否与宣称一致；
2. 关键能力是否完整；
3. 响应与流式协议是否合规。

### 1.2 核心价值主张

**不靠口号判断接口，靠公开证据完成真测。**

### 1.3 品牌人格

| 特质 | 我们是 | 我们不是 |
|---|---|---|
| 克制 | 信息优先、装饰适量 | 空洞、冷漠或故意难懂 |
| 严谨 | 给出条件、单位、基线与证据 | 用“绝对”“100%”替代证明 |
| 透明 | 结果可追溯、规则可解释 | 用黑箱结论制造权威感 |
| 精密 | 对齐准确、层级清楚、状态明确 | 视觉堆叠或过度炫技 |
| 可信 | 尊重 API Key、隐私与原始语义 | 暗示未经证明的背书 |

### 1.4 品牌语言

- 默认语气：冷静、直接、具体、基于证据。
- 先说结论，再给依据；错误信息先给可理解摘要，再提供技术详情。
- “检测”“基线”“评分”“报告”“证据”等领域术语沿用上游定义。
- 时间、百分比、Token、延迟、数量必须带单位。
- 产品名、Slogan 不改写、不拆词、不创造其他简称。

推荐用语：

- `开始真测`
- `查看检测报告`
- `本次检测`
- `检测条件`
- `证据详情`
- `基线对比`
- `任务已提交，正在等待执行`
- `检测未完成，请查看失败原因`

禁用用语：

- `一键封神`
- `绝对真实`
- `完美模型`
- `全球领先`
- 无上下文的 `确定`、`好的`、`失败了`

## 2. 不可变边界

这次二开是视觉与品牌层改造，不是产品核心重写。

### 2.1 必须保持

- `src/relay_detector/` 的检测器、协议客户端、Runner、评分、报告 Schema 和 CLI 行为。
- `data/baselines/` 的官方基线内容与选择逻辑。
- 异步任务状态、并发、持久化、API Key 生命周期和错误语义。
- 排行榜聚合、贝叶斯排序、中位分展示和过滤规则。
- 所有现有页面路由、HTTP 方法、请求字段、响应字段、状态码和下载格式。
- 报告中的分数、Verdict、Detector 状态、字段证据和原始数据。
- 上游 AGPL-3.0-or-later 许可证、来源说明和公开源代码入口。

### 2.2 禁止

- 因换肤重写业务状态机、数据转换或协议请求。
- 前端自行定义新的合格线、评分等级、任务百分比或排名规则。
- 为演示效果伪造检测结果、实时进度、排行榜数据或成功状态。
- 新增后端并未支持的取消、重试、导出、筛选等动作。
- 对整个仓库全局替换 `Veridrop`，从而误改核心代码、协议内容或历史测试。
- 引入 React、Vue、Tailwind、CSS-in-JS 或新的前端打包链。
- 借二开清理无关代码、重命名核心类型或重排基线数据。

### 2.3 可改范围

- Jinja 页面模板的语义结构、品牌文案和视觉层级。
- 原生 CSS 的 Token、布局、响应式、组件状态和动效。
- 原生 JavaScript 中与可访问性或视觉交互直接相关的手术式调整。
- Favicon、Open Graph、robots、sitemap、llms、分享图和页面元数据中的品牌与域名。
- Web 服务层中硬编码的品牌、Canonical、SEO 和下载文件名；不得改变路由或 Payload。
- README、FAQ、贡献说明等面向用户的二开文档，同时保留上游归属。

## 3. 设计原则

1. **证据优先**：评分、检测对象、时间、基线、证据和原始字段先于装饰。
2. **一个首要焦点**：每个首屏只设一个主标题、一个主要操作和一个核心结果。
3. **材质表达层级**：实色承载内容；玻璃只承载悬浮、覆盖、导航或短时操作层。
4. **黑白构成骨架**：中性色承担品牌；彩色只承担成功、警告、失败和信息语义。
5. **数据不失真**：视觉强调不得改变排序、比例、阈值、精度或结论含义。
6. **安静的高级感**：依靠排版、留白、边线与节奏，不依靠霓虹、光球或重阴影。
7. **渐进增强**：模糊、透明或动效不可用时，内容仍完整、清晰、可操作。
8. **可追溯改动**：每一处 UI 差异都能追溯到品牌、视觉、响应式、无障碍或 SEO 目标。

## 4. 原创视觉母题：Evidence Trace

Evidence Trace 用一条精细的中性色线串联：

`请求 → 探活 → 检测 → 基线 → 评分 → 报告`

它表达“从零到一”和“有据可鉴”，是零一智鉴区别于通用 SaaS 毛玻璃界面的核心母题。

规则：

- 使用 1px 线、4–8px 节点、短标签和明确的真实阶段。
- 只用于流程、报告章节导航、结果追溯或区块分隔。
- 单个视口最多出现一组完整 Trace，避免变成重复纹样。
- 未完成步骤使用空心节点，已完成步骤使用实心节点，错误步骤同时显示图标和文字。
- 后端未提供阶段时，不得根据时间自行推测当前步骤。
- 装饰版本必须标注“示例”，不可伪装成真实检测状态。

采用三层 Token：

`Primitive 原始值 → Semantic 语义值 → Component 组件值`

组件不得直接引用十六进制颜色、任意间距或任意动效时长。当前阶段在单一 CSS 文件中按三层分区即可，不为 Token 单独引入构建工具。

## 6. 排版系统

### 6.1 字体栈

界面字体：

```css
system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI",
"PingFang SC", "Noto Sans CJK SC", "Microsoft YaHei", sans-serif
```

代码与协议内容：

```css
ui-monospace, SFMono-Regular, Menlo, Consolas, monospace
```

不随项目分发 SF Pro 字体文件。数值、耗时、Token 数和排名统一使用等宽数字 `tabular-nums`。

### 6.2 字阶

| 样式 | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| Hero | `clamp(40px, 6vw, 72px) / 1.05` | 600–650 | 首页唯一主标题 |
| Page H1 | `clamp(34px, 4vw, 48px) / 1.10` | 600–650 | 页面标题 |
| H2 | `clamp(28px, 3vw, 36px) / 1.18` | 600 | 大区块标题 |
| H3 | `24px / 1.30` | 600 | 卡片组与报告章节 |
| Body Large | `18px / 1.65` | 400 | 引导说明 |
| Body | `15–16px / 1.65` | 400 | 正文 |
| UI Label | `14px / 1.45` | 500 | 表单、按钮、导航 |
| Meta | `12–13px / 1.50` | 400–500 | 辅助信息 |
| Metric | `clamp(40px, 5vw, 64px) / 1` | 600 | 核心分数或指标 |

规则：

- 中文正文不使用全大写效果或夸张字距。
- 小于 14px 的文字只用于非关键短标签，不承载长文本。
- 标题最大字重 650，避免大面积 700–900 粗体。
- 正文行宽控制在 64–72 个字符，技术明细除外。

## 7. 布局系统

| 视口 | 网格 | 页面边距 | 区块纵向间距 |
|---|---|---|---|
| `<640px` | 4 列 | `16px` | `56–72px` |
| `640–1023px` | 8 列 | `24–32px` | `72–96px` |
| `≥1024px` | 12 列 | `32–48px` | `96–128px` |

- 移动端按自然阅读顺序变为单列。
- 除代码块和数据表外，不产生页面级横向滚动。
- 点击目标至少 `44 × 44px`。
- 在 320px CSS 宽度和浏览器 200% 缩放时不得丢失关键功能。
- 标题使用 `clamp()`，不按具体设备型号写断点。
- 若使用 Sticky 元素，必须为系统安全区和键盘焦点留出空间。

层级固定为：

| 层级 | z-index |
|---|---:|
| 页面内容 | 0 |
| Sticky 导航 | 10 |
| Popover / Dropdown | 20 |
| Modal / Drawer | 30 |
| Toast | 40 |

## 8. 毛玻璃材质规范

### 8.1 允许位置

- Sticky 顶部导航；
- Popover、Dropdown、Modal、Drawer；
- 浮动操作栏；
- Hero 中面积有限、明确标注的结果预览；
- 有真实背景内容可被感知的悬浮层。

### 8.2 推荐参数

浅色：

```css
background: rgba(255,255,255,.68);
backdrop-filter: blur(24px) saturate(110%);
border: 1px solid rgba(255,255,255,.58);
```

深色预留：

```css
background: rgba(18,18,18,.72);
border: 1px solid rgba(255,255,255,.12);
```

### 8.3 使用限制

- 长文本、表格、代码块、表单主体和核心结果面板使用实色或接近实色的表面。
- 一个区域最多两层透明材质，禁止“玻璃套玻璃”。
- 静态卡片主要用边框和背景区分，不默认加阴影或悬浮动画。
- 不使用彩色霓虹描边、大面积模糊光球、彩虹渐变或持续移动高光。
- 不支持 `backdrop-filter`、强制色彩、高对比或降低透明度环境时，退化为实色表面。
- 玻璃背景必须先满足文字 4.5:1 对比度，再讨论透明度。

## 9. 页面规范

### 9.1 首页 `/`

- 首屏仅包含产品名、固定 Slogan、一个主操作、一个次操作和一处证据预览。
- 使用原创 7/5 非对称网格：左侧价值表达，右侧 Evidence Trace 或明确标注“示例”的真实界面预览。
- 后续顺序：支持协议 → 真测能力 → 证据链 → 报告结构 → 排行榜/公开结果 → 最终 CTA。
- 不使用“行业第一”“100% 准确”等无法被报告证明的营销结论。

### 9.2 协议检测页 `/claude`、`/openai`、`/gemini`

- 主输入和主提交按钮处于第一视觉层。
- API Key 默认遮蔽，并保留密码管理器、复制粘贴和键盘兼容性。
- Label 在输入框外，不以 Placeholder 代替 Label。
- 帮助文案与错误信息通过语义关系绑定控件。
- 高级参数只呈现上游已有能力；不发明新的模式或开关。
- 提交后沿用现有任务创建、错误恢复和页面跳转行为。

### 9.3 异步任务页 `/r/{job_id}`（运行中）

- 明确展示任务 ID、真实状态、创建/更新时间和后端实际提供的阶段。
- 后端没有百分比时使用不定进度，不计算虚假百分比或倒计时。
- 状态变化使用 `aria-live="polite"` 通知。
- 不新增后端没有的取消或重试按钮。

### 9.4 报告页 `/r/{job_id}`（完成）

阅读顺序固定为：

1. 总体结论与总分；
2. 检测对象、模型、协议、时间与模式；
3. 各检测维度；
4. 证据和协议详情；
5. 基线或比较信息；
6. 可追溯元数据与分享操作。

技术原始数据可以折叠，但不可丢弃或改写。分享、JSON 和 JPG 链接继续使用现有路由与格式。

### 9.5 排行榜 `/leaderboard`、`/leaderboard/{domain}`

- 排名算法、排序依据、过滤规则和显示精度保持不变。
- 数字右对齐并使用等宽数字。
- 状态不能只靠红绿颜色表达，必须有文字或图标。
- 移动端可横向滚动表格；只有不损失关键语义时才转成卡片。
- 不隐藏决定排名含义的核心列。
- Sticky 表头可使用实色或轻透明背景，避免多层玻璃叠加。

### 9.6 FAQ `/faq`

- 保持现有问答内容和模式持久化行为。
- 目录、标题和展开控件支持键盘。
- 正文使用长文阅读宽度，不使用玻璃卡片承载长段落。

### 9.7 JPG 报告卡片

- 保留现有 1400 × 1000 输出尺寸、JPG 媒体类型、报告字段和路由契约。
- 替换为零一智鉴品牌、域名和中性设计语言。
- 不因版式省略总分、结论、检测对象、时间或关键证据。

## 10. 核心组件

### 10.1 按钮

| 变体 | 样式 | 用途 |
|---|---|---|
| Primary | 黑底白字；深色主题反转 | 每屏唯一主操作 |
| Secondary | 透明/实色浅底 + 1px 边框 | 次级操作 |
| Ghost | 透明底，Hover 使用中性覆盖层 | 导航与低优先级操作 |
| Destructive | 功能红 + 明确文字 | 真实破坏性动作 |

- 默认高度 44px，紧凑型不低于 36px。
- 覆盖 default、hover、pressed、focus-visible、loading、disabled。
- Loading 时保持原宽度，避免布局跳动。
- Pill 只用于短状态或筛选，不把所有按钮做成胶囊。

### 10.2 输入控件

- 默认高度 48px，圆角 12px。
- Focus 使用 2px 高对比前景环 + 2px 背景偏移；必要时才使用信息蓝。
- 错误同时显示边框、图标、文字和 `aria-describedby`。
- URL、模型名、Header 等技术值可使用等宽字体，但不改变上游校验。
- API Key、Token、敏感 Header 继续遵循现有脱敏规则。

### 10.3 卡片与指标

- 移动端内边距 20px，桌面 24–32px。
- 不可点击卡片不提供悬浮抬升。
- 可点击卡片必须具有真实链接或按钮语义。
- 指标必须包含名称、值、单位、时间或上下文。
- 单一总分可以使用环形图；其他维度优先用对齐数值和水平条。

### 10.4 状态标签

- 高度 24–28px，只用于短状态。
- 由文字 + 图标/形状 + 必要功能色共同表达。
- 使用后端已有状态词，不创造与任务状态冲突的新名称。

### 10.5 表格

- 默认行高约 52px。
- 表头 12–13px、字重 500。
- 数字右对齐，文本左对齐，状态居中或按语义对齐。
- Hover 仅做轻微中性底色变化。
- Tooltip 支持键盘和触控，关键解释不可只存在于 Tooltip。

### 10.6 代码与协议详情

- 字号 `13px / 20px`。
- 长行横向滚动，不强制破坏 JSON、Header 或 SSE 格式。
- 复制操作提供明确的成功反馈和 Live Region。
- 不在 UI 层取消核心已有的敏感信息脱敏。

### 10.7 空、错、加载状态

- 空状态解释“为什么为空”，并提供一个明确下一步。
- 错误状态先给用户可理解的摘要，再展开技术详情。
- Skeleton 形状接近真实布局，避免整页闪烁。
- 未知时长使用不定进度，不伪造倒计时。

## 11. 数据可视化

- 仅当现有契约提供单一总分时使用环形分数图。
- 若分数契约为 0–100，图表固定为 0–100，不动态缩放放大差异。
- 合格线、等级和权重读取现有结果或基线，不在前端新定义。
- 多系列优先使用不同灰阶、线型和标记，颜色仅作辅助。
- 图表提供文本等价信息、单位、范围和可访问明细。
- 不使用 3D、装饰性仪表盘、粒子动画或无数据依据的趋势。
- 排名、延迟、稳定性等数值保留后端精度，不擅自重新计算。

## 12. 动效

| Token | 时长 | 用途 |
|---|---:|---|
| `motion-fast` | `120ms` | 按压、颜色反馈 |
| `motion-base` | `180ms` | Hover、Dropdown |
| `motion-enter` | `260ms` | Modal、Panel 进入 |
| `motion-slow` | `360ms` | 单次页面内容揭示，谨慎使用 |

- 主缓动：`cubic-bezier(.2,.8,.2,1)`。
- 优先动画 `opacity` 和 `transform`。
- Hover 位移最多 `-1px`。
- 页面进入动画只执行一次，不随滚动反复触发。
- 禁止自动播放视差、无限漂浮、频繁缩放和伪进度动画。
- `prefers-reduced-motion: reduce` 下关闭位移、视差和 Shimmer，只保留即时状态切换。

## 13. 无障碍

- 目标 WCAG 2.2 AA。
- 正文对比度至少 4.5:1；大字至少 3:1；控件边界、图形和焦点至少 3:1。
- 所有交互支持键盘，焦点顺序与视觉顺序一致。
- 提供 Skip Link、Landmark、语义化标题层级和正确表格表头。
- 不通过颜色、透明度或动画单独表达状态。
- Modal/Drawer 正确锁定焦点并在关闭后恢复焦点。
- 异步任务、复制成功、表单错误使用适当的 Live Region。
- 支持 `forced-colors`、减少动态效果和无法使用毛玻璃的环境。
- 图标按钮必须有可访问名称。
- 页面标题必须反映协议、任务、报告或排行榜上下文。

## 16. Do / Don’t

### Do

- 用留白、排版和对齐建立高级感。
- 用 Evidence Trace 强化“有据可鉴”。
- 让分数、状态、时间和证据形成稳定阅读路径。
- 只在真正悬浮的层级使用玻璃。
- 为每个状态提供文字和可访问反馈。
- 让每一处变更可追溯到明确需求。

### Don’t

- 不把每张卡片都做成半透明玻璃。
- 不使用霓虹、发光描边、粒子背景或大面积彩色渐变。
- 不复制 Apple 的设备构图、官方图标、字体文件或营销句式。
- 不为了“高级感”降低字号、对比度或信息完整性。
- 不伪造进度、实时数据、状态或营销结论。
- 不借换肤重构业务代码、数据模型或 API。
- 不顺手清理与 UI 二开无关的历史代码。
