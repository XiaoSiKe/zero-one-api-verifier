## Problem Statement

Veridrop 已经具备完整的 AI API 中转站检测能力，包括多协议客户端、模型探活、官方基线、检测器、评分、异步任务、报告、分享图片和排行榜。现有产品在功能上可以回答“接口是否真实、能力是否完整、协议是否合规”，但其品牌、域名和视觉体验仍属于 Veridrop，无法作为“零一智鉴 · API 真测雷达”对外提供统一、独立、可信的产品体验。

用户需要的不是一次核心重写，而是一次严格受控的 UI 二开：将产品统一为“零一智鉴 · API 真测雷达”，使用固定 Slogan“从零到一，让每一个接口有据可鉴！”，以 `https://mix.01yapi.cc` 作为唯一正式域名和 Canonical 基址，并建立极简黑白、精密留白、克制毛玻璃的原创视觉系统。与此同时，所有检测结果、协议行为、评分、报告字段、异步任务状态、排行榜算法和现有 API 契约都必须保持不变。

如果缺少清晰的边界和可验证的验收接缝，视觉改造很容易误伤原生 JavaScript Hook、表单字段、任务轮询、报告 Schema、搜索元数据或敏感信息处理；也容易因为全局替换品牌而改动受保护核心。项目还必须处理 Fork 的 AGPL-3.0-or-later 归属、运行版本源码入口，以及上游统计账号不能继续收集新域名访问数据的问题。

## Solution

在保留 Veridrop 核心和 HTTP 契约的前提下，为现有 FastAPI、Jinja2、原生 CSS/JavaScript Web 层建立并实施一套独立的零一智鉴品牌与 UI 系统。

方案以《零一智鉴 · API 真测雷达 — UI 设计规范》为唯一视觉基线，采用 Primitive → Semantic → Component 三层 Token，使用黑白中性色构成主体，仅以蓝、紫、蓝紫功能色表达成功、警告、失败和信息。Logo 直接使用用户提供的黑底白色原始资产，不重绘、不改色；Web 派生文件只裁去黑色安全区并缩放。毛玻璃只用于导航、弹层和有限悬浮层；核心表单、报告、表格和技术证据保持清晰、稳定的实色承载面。原创的 Evidence Trace 视觉母题用于表达“请求 → 探活 → 检测 → 基线 → 评分 → 报告”的真实证据链。

实施只触及品牌、模板、样式、必要的原生交互适配、分享图、SEO 静态资源和 Web 层硬编码元数据。检测核心、协议实现、官方基线、评分、任务、排行榜和对外 API 保持冻结。所有视觉修改通过现有完整 pytest 回归、页面路由/契约测试、浏览器核心流程、固定视口视觉快照和自动无障碍检查共同验收。

二开完成后持续采用“受控上游同步”：每次 Veridrop 更新都从零一智鉴最新 `main` 创建独立同步分支，先吸收上游核心更新，再恢复并保护下游首页、模板、样式和品牌资产。上游在 UI 层的安全、兼容和可访问性修复经过人工审查后适配迁入；任何同步都不能直接覆盖默认分支或静默恢复上游品牌。完整流程以[《零一智鉴上游同步与二开保护协议》](https://github.com/XiaoSiKe/zero-one-api-verifier/blob/main/zero-one-api-verifier/docs/UPSTREAM_SYNC_POLICY.md)为准。

## User Stories

1. 作为首次访问者，我希望立即看到“零一智鉴 · API 真测雷达”，从而确认自己进入了正确的产品。
2. 作为首次访问者，我希望看到固定 Slogan“从零到一，让每一个接口有据可鉴！”，从而快速理解平台强调真实证据。
3. 作为首次访问者，我希望首页只有一个清晰的主要行动，从而不用在多个同级按钮之间判断下一步。
4. 作为产品用户，我希望全站只出现一种中文产品名和一种英文产品名，从而避免品牌混乱。
5. 作为产品用户，我希望所有正式链接和 Canonical 都指向 `https://mix.01yapi.cc`，从而获得一致的分享与搜索体验。
6. 作为 Claude API 用户，我希望继续使用原有字段和参数提交检测，从而不需要学习新的工作流。
7. 作为 OpenAI API 用户，我希望继续使用原有字段和参数提交检测，从而不受视觉改版影响。
8. 作为 Gemini OpenAI 兼容 API 用户，我希望继续使用原有字段和参数提交检测，从而保持现有协议路径可用。
9. 作为 API 中转站用户，我希望 API Key 默认遮蔽，从而减少屏幕旁观和误分享风险。
10. 作为 API 中转站用户，我希望模型探活、候选模型和错误恢复继续工作，从而可以在提交前发现配置问题。
11. 作为 API 中转站用户，我希望死模型的 422 提示及强制继续能力保持不变，从而保留原有逃生路径。
12. 作为跨协议用户，我希望已有的协议识别和页面 Handoff 继续工作，从而不必重复输入相同配置。
13. 作为长上下文测试用户，我希望原有长上下文选项和字段保持不变，从而获得与改版前相同的检测覆盖。
14. 作为任务提交者，我希望提交成功后仍收到相同的任务标识和状态链接，从而保证现有前端流程和外部调用兼容。
15. 作为任务提交者，我希望运行页只显示后端真实提供的状态，从而不会被伪造的百分比误导。
16. 作为任务提交者，我希望任务状态变化能被屏幕阅读器播报，从而在不盯着动画时也知道进展。
17. 作为任务提交者，我希望运行页在任务完成后仍进入原有报告链接，从而保持流程连续。
18. 作为报告阅读者，我希望先看到结论和总分，再看到环境、维度和证据，从而快速建立判断。
19. 作为报告阅读者，我希望所有 Detector 名称、状态、分数、权重和证据与改版前一致，从而信任报告没有被 UI 篡改。
20. 作为技术审计者，我希望展开查看完整协议字段和原始证据，从而可以独立复核结论。
21. 作为报告阅读者，我希望时间、Token、延迟和百分比都有单位，从而避免误读。
22. 作为报告阅读者，我希望长 JSON、Header 和 SSE 内容保持格式并可横向滚动，从而不因强制换行损坏技术语义。
23. 作为报告分享者，我希望继续复制永久报告链接，从而可以把同一证据发给其他人。
24. 作为报告分享者，我希望继续下载相同格式和尺寸的 JPG 报告卡片，从而保持现有分享渠道兼容。
25. 作为 JSON 使用者，我希望原始报告下载接口和 Schema 保持不变，从而不必修改自动化脚本。
26. 作为排行榜访问者，我希望排名顺序与改版前完全一致，从而确定 UI 没有改变算法。
27. 作为排行榜访问者，我希望清楚看到排序含义、样本和中位分，从而理解榜单结论来自什么。

32. 作为移动端用户，我希望页面在 390px 视口下保持单列、可读和可操作，从而可以在手机上完成检测。
33. 作为平板用户，我希望页面在 768px 视口下保持清晰层级，从而不过早压缩成拥挤的桌面布局。

## Implementation Decisions

- 中文产品名固定为“零一智鉴 · API 真测雷达”，英文产品名固定为“ZeroOne · API Verification Platform”，仓库名固定为 `zero-one-api-verifier`。
- 固定 Slogan 为“从零到一，让每一个接口有据可鉴！”，任何页面、分享图或 SEO 文案不得改写。
- 正式域名与 Canonical 基址统一为 `https://mix.01yapi.cc`；Canonical、Open Graph、结构化数据、Sitemap、robots、llms 和报告分享链接必须同步。
- 设计规范是 UI 实施的视觉事实来源；实现不得在规范之外临时创造颜色、间距、字号、圆角或动效。
- 前端继续使用服务端模板、原生 CSS 和原生 JavaScript，不增加 JavaScript 框架、CSS 框架或打包链。
- 采用 Primitive、Semantic、Component 三层 Token；组件只引用语义或组件 Token。
- 默认界面使用黑白中性色；成功、警告、失败和信息色仅承担状态语义，并与文字或图标共同出现。
- 毛玻璃只用于 Sticky 导航、弹层、浮动操作栏和有限结果预览；表单、长文本、表格、代码和核心结果使用实色或高不透明表面。
- Evidence Trace 是原创视觉母题，只映射真实的请求、探活、检测、基线、评分和报告阶段；未知阶段不推断进度。
- 页面信息架构保持现有路由和业务入口，不借换肤新增产品功能或删除既有能力。首页固定提供一个主检测 CTA，并在可见内容中完整呈现定义、可核验统计、开源信任、三协议入口、检测步骤和结果边界说明。
- 三个协议检测表单的字段名、默认模式、长上下文选项、强制提交逃生口和提交 Endpoint 保持不变。
- 模型 Combobox、探活、跨协议 Handoff、死模型错误恢复、移动导航、FAQ 模式持久化、任务轮询和分享复制属于功能代码，改版必须保留。
- 异步任务只展示后端真实提供的状态；没有百分比时使用不定进度。
- 报告阅读顺序统一为结论与总分、检测元数据、各维度、证据详情、基线信息和可追溯元数据，但字段、含义和原始数据不变。
- 排行榜只改变呈现，不改变按域名聚合、样本门槛、贝叶斯排序、中位分展示、时间排序或隐藏规则。
- JPG 报告卡片允许品牌和视觉改造，但输出尺寸、媒体类型、路由、函数边界和报告字段读取保持不变。
- Web 路由层只允许手术式修改品牌、域名、SEO 元数据和下载文件名；校验、任务提交、状态 Payload 和错误结构保持不变。
- 检测核心包、三协议客户端与检测器、Runner、评分、报告 Schema、兼容层和官方基线数据均为冻结区。
- 任务管理、排行榜聚合、模型探活、限流和报告持久化均为冻结区。
- 对外 HTTP 契约全部保持，包括页面路由、探活、检测提交、任务状态、JSON 报告、HTML 报告、JPG 报告、健康检查和搜索静态资源。
- 提交成功 Payload、任务状态 Payload、死模型 422 Detail、DetectionReport 和 DetectorResult 的字段与语义保持不变。
- 品牌替换使用明确 Allowlist，不对整个仓库做全局字符串替换。
- 新域名不得继续使用上游 Google Analytics ID；本期默认移除，除非产品负责人另行提供已授权的自有配置。
- 所有源码和许可证入口指向当前 Fork，同时保留清晰的上游来源、Fork 基线和 AGPL-3.0-or-later 说明。
- 不复制 Apple 的字体文件、图标、设备资产、页面构图或标志性文案；Apple 仅作为精度、克制和材质层级的审美参考。
- 深浅色主题均为正式状态：首次跟随系统偏好，用户可在顶部导航切换并本地持久化；两套主题必须保持相同内容、交互、状态语义和 WCAG 2.2 AA 可读性。
- 顶部导航参考零一 API 首页的视觉行为：首屏为透明顶栏，滚动后收拢为居中毛玻璃胶囊；不复制其业务链接或页面内容。
- 页头 Logo 外部视窗固定恢复为 30 × 30px，仅将内部图形缩至约 78%，以增加黑色安全区，不改动源图和 Favicon 契约。
- 首页标题与 Slogan 使用原生 CSS/JavaScript 实现无彩色描边的逐字 Wipe，以及中性高光单程 `4s`、返程 `4s`的完整 `8s` 往返 ShinyText；CTA 采用显式 Allowlist 的 Specular 材质；滚动出现只做一次渐进增强，并完整尊重减少动态效果。
- WebGL Threads 只在首页挂载；其他路由不创建 Canvas 或 WebGL 上下文。任何 JavaScript、WebGL 或动效失效都不得隐藏首页核心内容或阻断主 CTA。
- 当前 Gemini 结果说明中的协议文案应与实际的 OpenAI-compatible Chat Completions 实现一致；只纠正文案，不改变协议实现。
- 所有交互目标至少 44 × 44px，并覆盖 Hover、Pressed、Focus Visible、Loading、Disabled 和 Error 状态。
- 响应式验收基准为 390px、768px 和 1440px；320px 与 200% 缩放用于防止关键功能丢失。
- 无障碍目标为 WCAG 2.2 AA，包含键盘流程、焦点管理、Live Region、强制色彩和减少动态效果。
- 分阶段实施顺序固定为：设计规范 → PRD 与 Issue → UI 实施 → 页面级验证；首页信息架构已收敛，当前进入页面级验证。
- 所有上游更新遵循独立 `sync/upstream-*` 分支、同步前 Tag、PR 审查和完整验证流程，不直接同步到 `main`。
- 上游优先区持续吸收检测核心、官方基线、任务和排行榜更新；完全保护区保留首页、模板、样式和品牌资产；业务与品牌混合文件逐段人工合并。
- 自动合并结束时，完全保护区必须恢复为同步前下游版本。上游对该区域的安全、兼容和可访问性修复以独立提交手工迁入，不使用整页或整文件覆盖。
- 禁止强制同步、重置默认分支、全局偏向上游的冲突策略，以及未经 PR 和验证的直接合并。
- 每个同步 PR 必须记录上次与本次上游 SHA、冲突处理、手工迁入内容、未迁入 UI 变化、测试结果和视觉对比。

## Testing Decisions

- 好测试只验证外部可观察行为，不绑定内部 CSS 选择器结构、私有函数或具体排版实现；视觉快照除外，且快照只覆盖稳定、代表性的页面状态。
- 最高层回归接缝是完整用户路径：选择协议、填写配置、探活/选择模型、提交、查看运行状态、进入报告、展开证据和分享。
- 为页面路由新增固定 Mock 数据的渲染/契约测试，验证状态码、品牌、Canonical、关键表单字段、报告链接和搜索元数据。
- 为公开 API 增加契约断言，确认请求字段、成功 Payload、422 Detail、任务状态 Payload、JSON 报告 Schema 和下载媒体类型未变化。
- 使用浏览器级 Smoke 测试覆盖移动导航、模型 Combobox、表单提交、任务轮询完成、FAQ 交互和复制分享链接。
- 使用 390px、768px、1440px 的固定视口保存首页、协议表单、运行中、完成报告和排行榜关键状态的视觉快照。
- 视觉回归使用稳定 Mock 数据、固定时区、禁用非必要动画和一致字体回退，避免把数据波动当作 UI 回归。
- 自动无障碍检查覆盖首页、协议表单、运行页、报告页、排行榜和 FAQ；严重或高优先级问题阻塞合并。
- 增加键盘人工/自动 Smoke：Skip Link、导航、表单、错误恢复、报告折叠、复制、表格与分页均可完成。
- 增加减少动态效果、无 `backdrop-filter` 和强制色彩的降级检查，确认内容与操作仍完整。
- 增加受保护核心差异守卫，以 Fork 基线提交为比较点，阻止检测核心和官方基线出现未授权功能差异。
- 增加完全保护区同步守卫：在手工迁入阶段之前，首页、模板、样式、Favicon 和品牌资产相对同步前 Tag 必须零差异。
- 已增加最小产品契约 `tests/test_zeroone_identity.py`，验证品牌、Canonical、当前 Fork 与上游归属、首页信息架构、Threads 页面边界、上游统计 ID 禁入和关键业务 Hook；不锁定字号、坐标、私有函数或动效实现常量。
- 上游同步 PR 必须重新运行页面流程、固定视口视觉快照和自动无障碍检查；任何未批准的 UI 差异阻塞合并。
- 同步验证必须确认上游核心更新已吸收，同时上游 UI 文件中的必要修复已有人工迁入记录。
- 每次 UI 实施都运行现有完整 pytest；它是评分、客户端、检测器、协议隔离、长上下文、探活、任务参数、排行榜、限流和 SEO 逻辑的零回归闸门。
- 现有评分、协议客户端、检测器、长上下文、探活、任务、排行榜、限流和 SEO 测试作为 Prior Art；优先复用其 Fixtures 和 Mock 风格。
- 当前仓库已具备上述静态产品身份契约，但仍没有页面 TestClient、模板渲染、JavaScript 单测、浏览器 E2E 或视觉回归；本项目只在最高页面层新增必要接缝，不先建设通用测试框架。
- CI 保持 Python 3.10、3.11、3.12 的 pytest 矩阵；现有非阻塞 Lint 策略本期不扩大。
- 验收要求：现有完整测试全绿、受保护核心差异守卫通过、页面/API 契约通过、关键浏览器路径通过、视觉差异经人工确认、自动无障碍无严重或高优先级问题。

## Out of Scope

- 修改检测器、协议客户端、模型配置、Runner、评分权重、Critical Veto、报告 Schema 或 CLI。
- 新增协议、新模型、新检测维度、新基线或新的评分口径。
- 修改异步任务状态机、并发上限、持久化、API Key 生命周期或错误结构。
- 修改排行榜聚合、样本门槛、贝叶斯排序、中位分、隐藏域名或时间规则。
- 修改现有 API 路由、HTTP 方法、请求字段、响应字段、状态码或文件格式。
- 引入 React、Vue、Svelte、Tailwind、组件运行时或 Node 前端构建链。
- 新增账号、登录、支付、订阅、后台、国际化系统或数据库迁移。
- 新增后端不支持的取消、重试、导出、筛选、通知或实时百分比。
- 引入账号级主题同步、服务端主题存储或新的主题 API；本期主题偏好仅保存在浏览器本地。
- 重构部署脚本、服务管理、目录结构或运维架构。
- 清理与品牌/UI 改造无关的旧代码、历史兼容层或文档债务。
- 对上游未授权的商标、视觉资产或背书关系作任何暗示。
