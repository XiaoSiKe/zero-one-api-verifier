常见问题(精选)

thinking signature 是什么?它能单独证明模型来源吗?

Claude 在思考问题时会返回一个不透明的 signature。 零一智鉴检查这个字段有没有被透传、形态是否异常。缺失或形态异常代表中转链路存在高风险, 但仍需结合其他检测项,不能只凭这一项断定模型来源。

thinking signature 是 Claude 启用扩展思考时,响应里 signature 字段返回的 服务端加密产物,长度 500-2000 字符。这个签名由 Anthropic 服务端生成, 当前零一智鉴检查该字段是否被完整透传及其长度形态,并把它作为 25% 权重的协议证据。 本服务不持有独立官方凭据做密码学验签,因此必须结合其他检测项判断风险。

Claude 中转站怎么挑?哪些信号说明它靠谱?

三步傻瓜判断:① 用零一智鉴测一次,总分 85 分以上说明多项协议、行为与能力证据表现良好, 但高分不等于官方身份认证;② 看页面有没有「严重」标记, 有就说明它可能在偷换模型,直接换一家;③ 去红黑榜查这家中转站 的历史记录,看其他人测出来什么样,测过 10 次以上仍稳定高分的更可信。 便宜的中转站多半有水分,看分数比看价格重要。

关键看 4 点:① 跑零一智鉴 full 模式看 thinking signature 是否拿到 100 分; ② 看 usage 字段有没有 claude_* 之外的异源痕迹 (e.g. usage_source: anthropic 出现在 OpenAI 响应里说明被中转套壳); ③ 看 stream / non-stream 在同一 prompt 上的 input_tokens / output_tokens 差是否 ≤ 5%; ④ 看消息 id 是否符合 msg_ / toolu_ / srvtoolu_ 前缀规范, UUID-like id 是中转站常见伪造手法。

Kiro / Amazon Q 包装层风险怎么发现?

有些中转站后端其实用的是 Amazon 自家"包装过的 Claude"(产品名叫 Kiro 或 Amazon Q)。 Amazon 这版会把 Claude 的思考"指纹"删掉 — 因为他们走的是简化接口。 零一智鉴会把 thinking signature 缺失记为高风险证据, 再结合身份、行为、能力和协议特征给出整体结论。

Kiro 和 Amazon Q 是 Amazon 的 Claude 替身网关,走 AWS Bedrock 的简化接口, 响应里不返回 thinking signature(签名生成需要 Anthropic 的私钥, Bedrock 端不实现该路径)。零一智鉴在 thinking_signature detector 上判 0 分, 该项 25% 历史权重归零,再与其他检测项一起进入加权计分。 它是高风险证据,但不是单项否决规则。
